# Ask Your Data

Ask plain-English questions about the campus electricity SQLite database. The
existing agent uses Gemini through its OpenAI-compatible API, a Python tool loop,
and a Streamlit chat interface.

## Architecture

- `streamlit_app.py` renders chat messages, retains the current conversation, and
  shows each assistant response's tool trace.
- `loop.py` sends the system prompt, recent chat history, and tool definitions to
  Gemini. It executes `get_schema` and `run_sql` calls and returns the answer,
  errors, turn count, and trace.
- `tools.py` reads the local `campus.db` database. The database is generated by
  `make_db.py` from the synthetic campus data.
- `evals/questions.json` contains evaluation prompts and expected behavior;
  `run_evals.py` runs selected prompts against the live model and appends JSONL
  results under `evals/`.

## Setup

Use Python 3.10 or later. Install the application dependencies:

```sh
python3 -m pip install -r requirements.txt
```

Create a `.env` file in the project root and set:

```dotenv
GEMINI_API_KEY=your_gemini_api_key
# Optional; defaults to gemini-3.8-flash
GEMINI_MODEL=gemini-3.8-flash
```

The project includes a local `campus.db`. If you need to generate it, run
`python3 make_db.py`; this creates or replaces the generated local database.

## Run the application

```sh
streamlit run streamlit_app.py
```

Ask questions in the chat input. **New Chat** clears the current conversation.
The assistant messages retain their expandable tool traces for debugging.

## Evaluations

Evaluation runs call the configured live Gemini model and may incur API usage.
Run selected question IDs or a split:

```sh
python3 run_evals.py --ids 1 2
python3 run_evals.py --split dev
python3 run_evals.py --split test --sleep 1
```

`--model MODEL` selects a model. `--sleep SECONDS` pauses between questions.
Each run appends JSON Lines to `evals/results_<model>.jsonl`. Some cases require
manual review; the runner labels them `needs_review`. Numeric expected answers
are checked against the expected values and order, alongside required phrases.

**Choose a scope before running evaluations.** If you provide neither `--ids`
nor `--split`, the runner executes the entire evaluation dataset. This sends
requests to the live Gemini API for all selected questions and may incur API
usage. Prefer `--ids` for a small targeted check or `--split dev` / `--split
test` for a subset. The runner also verifies that the database still contains
exactly 11,520 readings after the destructive-query safety cases (questions
21, 30, and 35).

## Automated tests

Install development dependencies and run the deterministic test suite:

```sh
python3 -m pip install -r requirements-dev.txt
python3 -m pytest
```

The tests use a temporary SQLite database and mocked model responses. They do
not modify the campus database or call Gemini.

## SQL safety

`run_sql` only accepts a single statement whose first SQL keyword is `SELECT` or
`WITH`. SQLite's read-only URI mode and `query_only` setting protect the
connection; an SQLite authorizer permits only query, read, and function actions
and denies write, schema, attachment, and pragma actions. Multi-statement input
is rejected by SQLite's single-statement execution API. Queries have a two-second
SQLite progress-handler deadline and return at most 50 rows. Database error
details are replaced with generic tool errors. `get_schema` uses a read-only
connection to inspect table metadata and sample rows.

## Conversation history and ambiguity

The UI passes only the most recent 10 user or assistant messages to the model,
with each message capped at 2,000 characters. Tool calls and SQL results are
shown in the UI trace and are not included in that history. The system prompt
asks the model to request concise clarification when essential context is
missing, and to use prior chat messages to resolve follow-ups when possible.
Clarification quality depends on model behavior and is covered with deterministic
mocked tests as well as manual-review evaluation cases.

## Errors and limitations

Model timeouts are retried once and HTTP 503 responses up to three times; 429
responses are returned without retry. The UI translates known API and agent
errors into user-facing messages while server logs retain diagnostic exception
details. SQL queries are bounded by a progress-handler deadline, though SQLite
cannot interrupt every blocking operation at the exact deadline. Ambiguous
question detection is prompt-guided rather than a separate deterministic
classifier. Live evaluation results depend on Gemini availability and model
behavior.
